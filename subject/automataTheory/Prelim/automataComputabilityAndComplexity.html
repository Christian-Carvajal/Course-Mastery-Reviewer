2. Limitations of Computer Science

Major reasons useful calculations cannot be done:

  1. Execution time of program is too long:
    Problem can take years or centuries to finish.
  2. Problem is not computable:
    No computer program can solve the problem.
  3. We do not know how to write a program to solve the problem:
    Problems that can conceivably be solved; includes many problems in artificial intelligence and computer vision, such as understanding language, object recognition, tracking, prediction.

3. Decision Problems & Problem Reduction

What problems can be solved by computers?

  • Equivalent to: “What decision problems can be solved?”
  • Decision problem: Problem where the answer is always YES/NO.
  • Arbitrary problem can always be reduced to a decision problem.
  • There are decision problems for which algorithms do not exist:
    • There are more different decision problems than there are different programs.
    • If there are more decision problems than programs, then it must be the case that some decision problems cannot be solved by programs.

Decision Problems vs. Particular Answers

Decision Problem (YES/NO) Particular Answer Required
Is 613,511 a prime number? (NO) What is the smallest prime factor of 613,511?
Is my birthday on a Sunday next year? (NO / YES) On what day of the week is my birthday next year?
Will I pass the Automata final exam? What grade will I get on the Automata final exam?

The process of answering questions where a particular answer is uniquely determined from the given information can be viewed as the evaluation of a function.

4. Functions & Computability

Definition

A function is a correspondence between a collection of possible input values and a collection of output values such that each possible input is assigned a unique output.

Function Characteristics & Examples

  • Addition function example: Inputs are value pairs, outputs are values representing the sum of each input pair. Output is unique, exactly one value for each input pair.
  • Function evaluation: The process of determining output for given input is called computing or evaluating the function.
  • The ability to evaluate functions gives us the ability to solve problems (e.g. to solve the addition problem we must evaluate the addition function).
  • Evaluation examples:
    • F(x) = x + 1 → F(2) = 3
    • F(x,y) = x + y → F(2,3) = 5

Computable vs. Noncomputable Functions

  • Algorithms: The means by which we formally express the evaluation of a function.
  • Can we design algorithms to evaluate ALL functions? No!
  • Noncomputable functions: Functions so complex that there is no well-defined step-by-step process for determining their output based on their input values. The evaluation of these functions lies beyond the capabilities of any algorithmic system.
  • Computable functions: Functions whose output values can be determined algorithmically from their input values (functions having an algorithm that solves them).

Limitations of Machines & Alien Life Question

  • Machines can only perform computations described by algorithms: the study of computable functions is the study of the ultimate capabilities of machines.
  • If we can build a machine with the capabilities to evaluate the entire set of computable functions, then the machines we build are as powerful as we can make them.
  • If we discover that the solution to a problem requires the evaluation of a noncomputable function, we know the solution to that problem lies beyond the capabilities of machines.
  • Q: Is it possible to write a Java program to answer: Does extraterrestrial life exist?
    A: Yes! The question is answered either by a program that returns “yes” or by a program that returns “no”. We just don’t know which program is correct.
  • Is a problem Computable? Suppose we create a list of all programs for evaluating computable problems. To ask whether a problem is computable is to ask if there is a program in the list to solve the problem. This is not the same as actually identifying the program in the list that solves the problem. There are many computable problems whose solutions have not yet been identified.

5. Abstract Model of Computation & Turing Machines

Turing Machine (1936)

The first abstract model of computation was defined by Alan Turing in 1936: The Turing Machine.

  • A Turing Machine is a purely theoretical device, developed well before technology was capable of providing the machines we know as “computers” today.
  • Model to study the capabilities and limitations of computational processes and computing machinery.
  • Provide a context in which solutions to all things computable can be expressed.
  • Provide a standard to which the power of other computational systems can be compared.

Turing-Computable ⇔ Computable

  • A function is computable if it can be computed by a Turing machine;
  • or, a function is computable if a program exists that can compute it;
  • or, a function is computable if there is an effective algorithm for evaluating the function which, given any input values for which the function is defined, produces the correct result and halts in a finite amount of time.
  • Q: Is there anything a Turing Machine cannot do? A: Yes!
  • Noncomputability: A function is noncomputable if there is no Turing machine that could compute it, or any function that cannot be computed by any program. There are many more functions than there are programs, so it is not possible to have a program for every function.
  • Noncomputable problem example: List all subroutines that input an integer and return an integer (e.g. int sub1(int x) { return 1; }, int sub2(int x) { return 2; }). Can make infinitely many such subroutines.

6. Halting & The Halting Problem

Halting Behavior

  • Programs that run forever do not halt: (e.g., programA with infinite loops).
    int programA(int x) {
      while(x == x)
        x = x;
      return x;
    }
  • Programs may halt on some inputs but not on others: (e.g., programB).
    int programB(int x) {
      while(x > 10)
        x = x;
      return x;
    }
  • Programs with no loops always halt: Programs composed of assignment statements, if statements and the return statement.

Halt or Not? (Code Analysis)

  • Loop 1:
    while(x > 1) {
      if(x > 2)
        x = x - 2;
      else
        x = x + 2;
    }
    If x = 8: 8 → 6 → 4 → 2 → 4 → 2 (Infinite loop, does not terminate).
    If x = 9: 9 → 7 → 5 → 3 → 1 (Terminates when x = 1).
  • Loop 2 (Collatz-like):
    while(x > 1) {
      if(x % 2 == 0)
        x = x / 2;
      else
        x = 3*x + 1;
    }
    If x = 8: 8 → 4 → 2 → 1 (Terminates).
    If x = 7: 7 → 22 → 11 → 34 → 17 → 52 → 26 → 13 → 40 → 20 → 10 → 5 → 16 → 8 → 4 → 2 → 1 (Terminates).

The Halting Problem & Proof of Noncomputability

  • The Question: Is it possible to write a Java program to answer: Does a given program halt on all inputs?
  • It would be useful if we could write a program or compiler to test if a given source program contains an infinite loop, so we would never execute a program with an infinite loop.
  • The Halting Problem is noncomputable: There is no single finite program that will answer the halting question for all programs. No finite program can be written that will check other programs and halt in a finite time giving a solution to the halting problem.

7. Program Execution Time: Tractable vs. Intractable Problems

Program Execution Time: How long a program takes to perform computations on large inputs. Computable problems are basically divided into two classes:

Class Definition & Complexity Examples
Tractable Computations that can be completed in a reasonable time period. Running time on N inputs is logarithmic or polynomial in N. • Searching or sorting N inputs
• Computing the sum of positive integers of size N
• Finding the largest element in an N x M array
• Counting the number of characters in a Java program
Intractable Computations that cannot be realistically completed except for small examples. Running time on N inputs is exponential in N. • Computing all permutations of N inputs
• Towers of Hanoi
• Traveling Salesperson
• Bin Packing
• Graph Coloring

Detailed Intractable Problem Descriptions

  • Towers of Hanoi: How long to move n disks? (Impractical / exponential).
  • Traveling Salesperson Problem: A traveling salesperson must visit each of some number of cities before returning home; knows the distance between each of the cities; wants to minimize the total distance traveled while visiting all of the cities. (Requires trying all paths from every starting point).
  • Bin Packing: Pack a given set of items having different sizes into a minimum number of equal-sized bins. Example: Pack trucks with barrels using the smallest possible number of trucks.
  • Graph Coloring: Color the vertices of a graph such that no edge connects two identically colored vertices using the minimum number of colors.

🏛️ Pillar 1: Core Terminology & High-Yield Keyword Recall Grid

Essential academic definitions and exact theoretical vocabulary required for exam question recall.

Decision Problem

Decision Problem: A computational problem where the answer is strictly binary: YES or NO (e.g., "Is 613,511 a prime number?"). All arbitrary computation problems can be formally reduced to decision problems.

Function

Function: A unique mathematical correspondence between a collection of possible inputs and outputs such that each input value is assigned exactly one unique output.

Function Evaluation

Function Evaluation (Computing): The mechanical or algorithmic process of determining the output value corresponding to given input values (e.g., evaluating F(x, y) = x + y → F(2, 3) = 5).

Algorithm

Algorithm: A formal, finite step-by-step mechanical procedure that explicitly specifies how to evaluate a function and solve a problem in finite time.

Computable Function

Computable Function: A function whose output values can be determined algorithmically from its input values by an effective program halting in finite time.

Noncomputable Function

Noncomputable Function: A function so complex that no step-by-step algorithmic process exists to determine its outputs from its inputs; its evaluation lies strictly beyond machine capabilities.

Turing Machine (1936)

Turing Machine: An abstract mathematical model of computation formulated by Alan Turing (1936). It provides the universal benchmark for computational power and formalizes what can and cannot be computed.

Turing-Computable

Turing-Computable: A function is Turing-computable ⇔ it can be computed by a Turing Machine ⇔ an effective algorithm exists that produces the correct result and halts in a finite amount of time.

The Halting Problem

The Halting Problem: The decision problem of determining whether an arbitrary program will eventually halt or run forever on a given input. Proved noncomputable / undecidable by Alan Turing in 1936.

Decidable (Language Class R)

Decidable Problem (Recursive / Class R): A decision problem for which an algorithm exists that halts on ALL valid inputs with a definitive YES (Accept) or NO (Reject) answer.

Turing-Recognizable (RE)

Turing-Recognizable (Recursively Enumerable / Class RE): A problem for which a Turing machine will halt and accept all YES inputs, but may loop indefinitely on NO inputs (Semi-Decidable).

Tractable Problem

Tractable Problem: Computations that can be completed in a reasonable time period. Its worst-case running time on input size N is logarithmic O(log N) or polynomial O(Nk) (e.g., sorting, array search).

Intractable Problem

Intractable Problem: Computable problems that cannot realistically be completed except for trivial input sizes. Its running time grows exponentially O(2N) or factorially O(N!) (e.g., TSP, Towers of Hanoi).

Class P

Class P: The class of all decision problems solvable by a deterministic sequential algorithm in Polynomial Time O(nk) (efficiently solvable).

Class NP

Class NP: The class of decision problems whose candidate solutions can be verified by a deterministic algorithm in polynomial time, or solved by a non-deterministic machine in polynomial time.

NP-Complete

NP-Complete: The hardest problems in Class NP. If any single NP-Complete problem is solved in polynomial time, every problem in NP is in P (proving P = NP).

Countable Infinity (ℵ₀)

Countable Set (ℵ₀): A set with the cardinality of natural numbers. The set of all possible computer programs and algorithms is countably infinite (ℵ₀) because each program is a finite string.

Uncountable Infinity (2^ℵ₀)

Uncountable Set (2ℵ₀ = ƒ): The set of all possible decision problems / mathematical functions is uncountably infinite (continuum). Because 2ℵ₀ > ℵ₀, noncomputable problems must exist.

1. Uncomputability Cardinality Inequality
|Programs| = ℵ₀ < |Decision Problems| = 2ℵ₀

When to Use / Verbalization: Proving why uncomputable functions exist. Computer programs are finite strings (countably infinite ℵ₀), whereas decision problems map to the power set of inputs (uncountably infinite 2ℵ₀).

Plain English Meaning: There are infinitely more problems than there are programs, so some problems mathematically cannot have any solving program.

💡 Exam Problem: Why must uncomputable decision problems exist in computer science?
Mathematical Proof: Cardinality of all valid programs is ℵ₀; cardinality of characteristic functions is 2ℵ₀. By Cantor's Theorem, ℵ₀ < 2ℵ₀, guaranteeing an uncountably infinite deficit of programs.
🗣️ How to Read in English
Read as: "The set of all computer programs is countably infinite (aleph-null), which is strictly smaller than the uncountably infinite set of decision problems (two to the power of aleph-null). Hence, uncomputable problems must exist."
2. Big-O Growth Rate & Tractability Boundary
O(1) ⊂ O(log n) ⊂ O(n) ⊂ O(n log n) ⊂ O(nk) ≪ O(2n) ⊂ O(n!)

When to Use / Verbalization: Categorizing algorithms as Tractable (Polynomial O(nk)) vs Intractable (Exponential O(2n) / Factorial O(n!)).

Plain English Meaning: As input size n increases, polynomial algorithms scale sustainably, whereas exponential/factorial algorithms explode into trillions of years.

💡 Exam Problem: Given n = 50 items, compare O(n²) vs O(2ⁿ) execution steps.
Solution: O(n²) = 50² = 2,500 operations (~2.5 µs). O(2ⁿ) = 2⁵⁰ = 1.125 × 10¹⁵ operations (~35.7 years at 1 GHz).
🗣️ How to Read in English
Read as: "Constant time O(1) is fastest, followed by logarithmic O(log n), linear O(n), linearithmic O(n log n), polynomial O(n^k) (the tractable boundary), exponential O(2^n), and factorial O(n!) (intractable)."
3. Towers of Hanoi Step Recurrence
T(n) = 2T(n - 1) + 1 &implies T(n) = 2n - 1

When to Use / Verbalization: Calculating the minimal move count to transfer n disks across 3 pegs. Demonstrates why recursive exponential problems are intractable.

Plain English Meaning: Doubling the problem size roughly doubles the already exponential execution time.

💡 Exam Problem: How many moves are required to solve the classic 64-disk Towers of Hanoi?
Solution: T(64) = 2⁶⁴ - 1 = 18,446,744,073,709,551,615 moves. At 1 move per second, this takes ~584.9 Billion years.
🗣️ How to Read in English
Read as: "The number of moves for n disks equals twice the moves for n minus one disks plus one, solving to two to the n-th power minus one moves."
4. Exhaustive Search & Permutations
P(n) = n!  |  ToursTSP = (n - 1)! / 2

When to Use / Verbalization: Calculating the search space for arranging n distinct elements or finding optimal symmetric Traveling Salesperson routes.

Plain English Meaning: Brute-force checking all combinations grows factorially, exceeding modern compute limits even for modest n.

💡 Exam Problem: How many unique round-trip tours must be evaluated to brute-force solve a 10-city symmetric TSP?
Solution: (10 - 1)! / 2 = 9! / 2 = 362,880 / 2 = 181,440 distinct tours.
🗣️ How to Read in English
Read as: "Total permutations of n items equals n factorial. For the Traveling Salesperson Problem, distinct undirected round-trip tours equal n minus one factorial divided by two."
5. Straight-Line Code Halting Invariance
Loops = 0 &implies DepthAST ≤ k &implies Halts = TRUE

When to Use / Verbalization: Identifying whether a given code fragment halts. Any program containing only assignments, basic arithmetic, branch conditionals (if/else), and return statements is mathematically guaranteed to halt.

Plain English Meaning: Without loops or recursion, a program has no mechanism to execute infinitely and must terminate in O(1) time.

💡 Exam Problem: Does a 500-line Java method with 50 nested if-else blocks and zero loops halt on input x = -999?
Solution: YES, guaranteed. Because control flow is acyclic, execution completes in finite steps along any branch.
🗣️ How to Read in English
Read as: "If a program has zero loops and zero recursion, its syntax execution tree is finite, guaranteeing the program will always halt."
6. Tractable Polynomial Upper Bound
T(n) ≤ c · nk  (for constants c > 0, k ≥ 0)

When to Use / Verbalization: Formal definition of Class P tractability. A computation is tractable if its time complexity is bounded by a polynomial in input size n.

Plain English Meaning: Even high polynomials like O(n⁴) are technically tractable, whereas exponential rates like O(2ⁿ) are intractable.

💡 Exam Problem: Is matrix multiplication of two n × n matrices (O(n³)) tractable or intractable?
Solution: Tractable, because degree k = 3 is a fixed polynomial constant (Class P).
🗣️ How to Read in English
Read as: "An algorithm is tractable if its execution time T of n is upper-bounded by a constant c times n to the power k for non-negative constants c and k."

⚠️ Pillar 4: Common Exam Pitfalls, Fallacies & Trap Alerts

High-frequency student errors, counterintuitive theorems, and exam trick questions.

⚠️ The "Alien Life" Paradox Trap

Fallacy: "Does extraterrestrial life exist?" is noncomputable because humanity does not know the answer.
Truth: It IS computable! The question has a fixed constant answer. Either the 1-line program return YES; or return NO; is correct. A problem is computable if a solving program exists, regardless of whether humans currently know which program it is.

⚠️ Straight-Line Code Halting Theorem

Fallacy: All programs might enter infinite loops and have halting uncertainty.
Truth: Programs with NO loops ALWAYS halt! Any program composed exclusively of assignment statements, conditional if/else branches, and return statements has an acyclic execution graph and must terminate in O(1) time.

⚠️ Intractable ≠ Noncomputable

Fallacy: Intractable problems cannot be solved by computers at all.
Truth: Intractable problems ARE computable! Algorithms exist for TSP and Towers of Hanoi, but their exponential running time makes them impractical for large inputs. In contrast, Noncomputable problems (like the Halting Problem) have zero possible algorithms.

⚠️ Specific Halting ≠ Halting Problem Solution

Fallacy: Tracing a loop for specific inputs (e.g. x = 8 or x = 9) solves the Halting Problem.
Truth: Tracing individual inputs only determines behavior for that specific execution trace. Solving the Halting Problem requires a single general algorithm that decides halting for ALL possible programs on ALL possible inputs, which Turing proved impossible.

⚠️ P vs NP Containment Direction

Fallacy: P and NP are mutually exclusive complexity classes.
Truth: P ⊆ NP is mathematically proven! Every problem solvable in polynomial time is also verifiable in polynomial time. The open question is whether P = NP (whether efficient verification implies efficient solvability).

⚠️ Countability vs Uncountability Gap

Fallacy: Because there are infinitely many programs, we can write a program for every possible function.
Truth: The infinity of programs is Countable (ℵ₀), while the infinity of functions/problems is Uncountable (2ℵ₀). Cantor's diagonalization proves that uncomputable functions vastly outnumber computable ones.
