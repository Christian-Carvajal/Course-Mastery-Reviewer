2. What is an OS Structure?

Definition

An OS Structure refers to the way an operating system is organized into different components or layers and how these components interact to manage computer hardware and software resources.

3. The 5 Main OS Structures (Simple, Layered, Microkernel, Modular, Hybrid)

  1. Simple Structure
    • The operating system is written as a single large program.
    • All components can communicate directly.
    • Easy to design but difficult to maintain.
    • Example: MS-DOS.
  2. Layered Structure
    • The OS is divided into layers.
    • Each layer performs specific functions and communicates only with the adjacent layers.
    • Each layer only communicates with the layer directly above or below it.
    • This layered design makes the operating system easier to develop, debug, maintain, and secure because each layer has a specific responsibility.
    • Example: THE Operating System.
  3. Microkernel Structure
    • Only essential services (such as process management and memory management) run in the kernel.
    • Other services (file system, device drivers) run in user space.
    • More secure and reliable but may have slightly lower performance.
    • Example: Minix, QNX.
  4. Modular Structure
    • The OS consists of separate modules that can be loaded or unloaded as needed.
    • Provides flexibility and better performance.
    • Example: Linux.
  5. Hybrid Structure
    • Combines features of monolithic and microkernel designs.
    • Balances performance and modularity.
    • Example: Windows, macOS.

4. Operating System Components & Layers

Operating System Structure Layers (Diagram Order)

  • Applications
  • System Libraries
  • System Call Interface
  • Hardware

Component Definitions

  • User Applications: Programs used by end users, such as web browsers, Microsoft Office, media players, and games.
  • System Programs: Utilities and software that help users interact with the operating system, such as command-line shells, compilers, and file managers.
  • System Call Interface: Acts as the communication bridge between user programs and the operating system kernel.
    Example system calls: open(), read(), write(), fork(), and exit().
  • Operating System Kernel: The core of the operating system. Responsible for:
    • Process Management
    • Memory Management
    • File Management
    • Device Management
    • Security and Protection
  • Hardware: The physical components of the computer, including the CPU, memory (RAM), storage devices, keyboard, mouse, monitor, printers, and network devices.

5. Major Operating System Structures: Monolithic Kernel In-Depth

The two major operating system structures highlighted are:

  1. Monolithic Architecture
  2. Microkernel Architecture

Monolithic Architecture

A Monolithic Architecture is an operating system design where all OS services run together in a single large kernel operating in kernel mode. All components can directly communicate with each other because they share the same memory space.

A Monolithic Architecture is an OS structure where all operating system services execute within one large kernel and directly interact with each other to manage system resources efficiently.

How It Works

  1. User applications request services through system calls.
  2. The request enters the kernel.
  3. Kernel components communicate directly with each other.
  4. The kernel accesses the hardware and returns the result to the application.

Monolithic Characteristics

  • Single large kernel
  • All services run in kernel space
  • Components communicate directly
  • High performance due to fewer communication overheads
  • Easier access to hardware resources

Advantages

  • Fast execution and high performance
  • Efficient communication between components
  • Simple design for smaller systems

Disadvantages

  • Large and complex kernel
  • Difficult to maintain and debug
  • An error in one component can crash the entire system
  • Lower security because all services run with full privileges

Examples of Monolithic Operating Systems

  • Linux (traditional monolithic kernel with modular support)
  • UNIX
  • MS-DOS

2. Dual-Mode CPU Operation & System Call Lifecycle

User Mode (Ring 3)
Mode Bit = 1

• Runs user applications (Word, Chrome, games).
• Cannot directly access physical hardware or privileged CPU instructions.
• Must issue a System Call (software trap) to request OS services.

Kernel Mode (Ring 0)
Mode Bit = 0

• Runs the core OS kernel and device drivers.
• Has unrestricted access to all CPU instructions, memory registers, and hardware peripherals.
• Switches Mode Bit back to 1 before returning control to user app.

Core POSIX System Calls
API Primitives

• fork(): Creates a child process clone.
• open() / read() / write(): File descriptor I/O operations.
• exit(): Terminates calling process and returns status.
