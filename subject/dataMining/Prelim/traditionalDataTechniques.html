PART 1: Traditional Data Foundations & Pre-Processing

1.1 Where Traditional Data Sits on the Map

Five columns, one timeline. Everything in this deck lives in the very first column (Traditional Data).

1.2 What Exactly Is "Data"?

One word, three different meanings:

  • Raw facts: Untouched facts sitting on your server that cannot be analyzed yet.
  • Processed data: Cleaned data converted into a usable format.
  • Information: Meaningful output people can make decisions from.

All three answers are correct, and that is the problem. Splitting the term apart is what makes the techniques easy to place.

1.3 The Data Pipeline

Pipeline Steps
RAW DATA → PRE-PROCESSING → PROCESSING → INFORMATION
• Raw Data: Untouched facts sitting on your server. Cannot be analyzed yet.
• Pre-processing: Convert raw data into a usable, understandable format.
• Processing: Run the analysis on data that is now trustworthy.
• Information: Meaningful output people can make decisions from.
• Gathering Step: Data collection.
• Clean-up Step: Data pre-processing.

1.4 Raw Data, in Plain Terms

Three names for the same thing: raw data = raw facts = primary data. Three facts that define it:

  1. Cannot be analysed straight away: Nothing has been checked, corrected, or labeled yet. Running an analysis on it now would just produce confident nonsense.
  2. It sits on your server, untouched: Data accumulated and stored exactly as it arrived, in whatever shape the source handed it to you.
  3. Gathering it is called data collection: That is the very first step, happening before a single pre-processing operation runs.

1.5 Step 1 Data Collection

Two everyday ways companies accumulate raw facts:

  • Manual (Surveys): Ask people directly (e.g., rate product/experience on scale 1-10). You control the questions, but people answer selectively.
  • Automatic (Cookies): Collected without anyone typing anything. Cookies hand companies detailed info about user website activity. Huge volume, but messy and full of surprises.

1.6 Why Pre-process? Because Raw Data Lies

Real examples of errors in customer data:

  • AGE = 932: Someone mistyped or a system wrote garbage into the field.
  • NAME = United Kingdom: Country value landed in the wrong column.

Data like this must be marked as invalid or corrected before analysis. Data pre-processing is a group of operations that fixes the problems data gathering inevitably creates.

1.7 Technique 1 Class Labeling

Label each data point with its correct type, or arrange data by category:

  • Numerical: Numbers that can be manipulated mathematically. Examples: Number of goods sold daily, Average goods sold per day/month. Arithmetic means something.
  • Categorical: Information that cannot have mathematical manipulations applied to it. Examples: A person's profession, place of birth, product category.
  • The Test: The test is never how the value looks. It is whether the arithmetic means anything. Example: Customer ID (1001) looks like a number, but an average customer ID tells you nothing, making it categorical. Complaints filed (3) is numerical.

1.8 Technique 2 Data Cleansing

Also called data cleaning or data scrubbing. Goal: deal with inconsistent data.

  • 1. Inconsistent values: Misspelled US states must be corrected before anything else.
  • 2. Missing values: e.g., customer gives name and occupation, but no age.
    • Option A: Disregard the customer's entire record.
    • Option B: Enter the average age of remaining customers.
    Neither answer is automatic. Both cleansing and missing values must be resolved before processing.

1.9 Case-Specific Approaches

  • Balancing: When one group dominates the sample (e.g., 80% female / 20% male survey), trends lean toward women. Fix: take equal numbers from each group so ratio becomes 50-50.
  • Data Shuffling: Shuffling observations ensures any 100 consecutive entries are random and representative, improving predictive performance and avoiding misleading results.

1.10 How Traditional Databases Are Pictured & At a Glance

  • Entity Relationship Diagram (ERD): Complex, theoretical architecture illustration. Entities, relationships, attributes.
  • Relational Schema: Each rectangle is one data table, each line shows relationships (Customers, Orders, Products).
  • At a Glance: When: Beginning; Tools: R, Python, SQL, MATLAB, Excel, IBM SPSS; Roles: Data architect, Data engineer, Database administrator.
  • Misconception: 200,000 lines of data is not necessarily big data. Volume alone does not make it big; variety, variability, velocity, veracity matter too.

PART 2: Big Data Techniques

2.1 Same Backbone, More Variety

Big data does not throw the pipeline awayit stretches every step. What changes:

  • Far more data types than numerical and categorical.
  • Much wider range of cleansing methods.
  • Missing values become a far bigger problem.
  • New case-specific techniques: text data mining, data masking.

2.2 Class Labeling & Cleansing in Big Data

  • Class Labeling Expansion: Green (Numerical, Categorical) + Orange (Text data, Digital image data, Digital video data, Digital audio data).
  • Image & Audio Cleansing: Verification that image observations are ready; confirming audio quality adequacy.
  • Text Data Mining: Process of deriving valuable unstructured data from text across academic papers, blogs, online platforms, private Excel files.
  • Data Masking: Analyzes info without exposing private details by concealing original data with random/false data. (e.g. Anna Kruger / a.kruger@example.com / 4519 8823 0067 → Q7RTX Vbnm / x8k2@masked.local / **** **** 0067).

2.3 Visualizations & Where Big Data Shows Up

  • Rule of Thumb: A large number of intersecting lines almost always means you are looking at big data.
  • Social Platforms: 2 billion+ users (Volume), text/images/video/audio (Variety), real-time reporting/velocity.
  • Financial Trading: Daily close = 1 obs/day (traditional). Every 5 seconds = 4,680 obs/day (big data). Every second = 23,400 obs/day (big data).

PART 3: Business Intelligence (BI)

3.1 Explaining the Past

Pre-processing is done. BI combines data skills with business knowledge to explain past performance. Asks: What happened? When? How many units sold? Which region sold most?

3.2 The Chain: Observations → Measures → Metrics → KPIs

  1. 01 Observations: Single recorded facts (e.g., 1 month revenue, 1 new customer).
  2. 02 Measures: Observations accumulated together to show info (Quantification: representing observations as numbers). e.g., Q1 measure = $350 revenue, 50 customers.
  3. 03 Metrics: Values derived from measures with business meaning attached (e.g., Average quarterly revenue per new customer = $350 / 50 = $7). Exist for comparison.
  4. 04 KPIs: The few metrics tied tightly to main business objectives. Metric = page traffic from any user; KPI = traffic from users who clicked ad link.

3.3 Dashboard Filtering & Real-World Applications

  • KPI Dashboards: Keep executives and managers focused on main business objectives.
  • Price Optimization: Raise room rates when demand is high; drop rates to attract visitors when demand falls. Real-time vs historical comparison.
  • Inventory Management: Avoid Oversupply (stock nobody buys, waste, storage cost, cash tied up) and Undersupply (lost sales, customers go elsewhere). Uses seasonality patterns, over/under-stocked months, peak day/hour.

PART 4: Traditional Methods (Predictive Analytics)

4.1 From Analysis to Analytics

When using info to predict future values, you switch from analysis to analytics. Predictive analytics splits into Traditional Methods (classical stats) and Machine Learning (AI-driven).

4.2 Key Traditional Techniques

  • Regression: Quantifies causal relationships among variables (Y = B × X). Straight line sits as close to all dots as possible.
  • Logistic Regression: Non-linear model where vertical values are ones and zeros joined by an S-curve. Candidate screening: 1 = prob > 50%, 0 = at/below 50%.
  • Cluster Analysis: Groups observations that behave alike. e.g., House size vs price in 3 clusters (Small/expensive city centre, Big/cheaper far from city, Big/expensive nice neighbourhood).
  • Explanatory Variable Names: Four names for the same thing: Explanatory variable, Regressor, Independent variable, Predictor variable (X side).
  • Factor Analysis: Groups explanatory variables together (e.g., 100 survey questions collapse 3 animal attitude questions into 1 factor → ~10 factors).
  • Distinction: Clustering groups observations together. Factor analysis groups explanatory variables together.
  • Time Series: Follows development of values over time. Rule: Time ALWAYS goes on horizontal line because time is independent of every other variable.
  • Applications: UX survey (4 continental clusters = 4 separate tests), A/B Testing (A/B/n multivariate testing), Sales Forecasting (Time series holds it up, ML sharpens accuracy).

PART 5: Machine Learning (ML) & Generative AI

5.1 Core ML Concepts & 4 Ingredients

ML is a trial-and-error process where each consecutive trial is at least as good as the one before it. You hand it ONE final goal, not a rulebook. Four ingredients (Robot Archer analogy):

  1. 01 Data: Values model trains on (Quiver of arrows).
  2. 02 Model: Thing learned/refined (Bow usage).
  3. 03 Objective function: Measure of how wrong you currently are (Average distance from target).
  4. 04 Optimization algorithm: Mechanics that reduce error (Adjusting posture, grip, draw strength).

The Loop: Fire arrows → Measure error → Adjust technique → Fire again closer. Training stops when good enough or after chosen arrows. Unseen inputs cause model to struggle.

5.2 The Three Major Types of Machine Learning

  • Supervised Learning: Known target for every arrow before shot (Labelled data). Approaches: SVMs, Neural networks, Deep learning, Random forest, Bayesian networks.
  • Unsupervised Learning: No targets provided (Unlabelled data); divides arrows into clusters/heaps. Approaches: K-means (most common), Neural networks, Deep learning.
  • Reinforcement Learning: Maximises a reward instead of minimising error (Positive reinforcement).
  • Deep Learning: Conceptually different, state-of-the-art, sits in both supervised and unsupervised due to broad scope and high accuracy.

5.3 NLP, Self-Supervised Learning & LLMs

  • Natural Language Processing (NLP): Subfield for written/spoken human language (Siri, chatbots, translators). Hybrid supervised/unsupervised.
  • Self-Supervised Learning: Unlabelled data → generates own labels → learns from them. Cornerstone of LLMs (ChatGPT, Gemini). Core trick: predicting the missing word using preceding context.
  • LLM Lineage: N-grams → RNNs → LSTMs → Transformers (2017 architecture using Attention / Self-attention mechanism).
  • GPT Unpacked: G = Generative, P = Pre-trained, T = Transformer.
  • Other GenAI Families: Diffusion models (images/video), GANs (two algorithms: generator & evaluator), NeRF (3D modelling), Hybrid models.

5.4 Real-World Applications

  • Fraud Detection: Bank card transactions with labels (Legitimate vs Fraudulent) = Supervised learning flagging theft in real time.
  • Client Retention: Large chains automate shop owner instinct by passing labelled data to model to identify likely buyers, lowering costs.

🧮 Part 1 (1.8): Data Cleansing — Min-Max Normalization & Z-Score Standardization
Input a raw observation value X alongside feature distribution bounds to compute bounded Min-Max scaling X_norm in [0, 1] and Z-Score standardization Z = (X - μ) ÷ σ.
Transformed Values: X_norm = 0.2500 | Z = -0.2500
Mathematical Transformation Steps:
• Min-Max Scaling Formula: X_norm = (X - X_min) ÷ (X_max - X_min) = (75 - 50) ÷ (150 - 50) = 25 ÷ 100 = 0.2500 (Bounded strictly in [0, 1])
• Z-Score Standardization: Z = (X - μ) ÷ σ = (75 - 80) ÷ 20 = -5 ÷ 20 = -0.2500 (0.25 standard deviations below population mean)
🧮 Part 4 (4.2): Traditional Methods — Simple Linear Regression (Ŷ = β₀ + β₁X) & Residual Error Estimator
Model bivariate causal relationships where X is the explanatory independent variable and Ŷ is the predicted dependent continuous response.
Predicted Response Ŷ & Residual Error: Ŷ = 45,000.00 | Residual e = +1,500.00
Linear Model Interpretation:
• Regression Formula: Ŷ = β₀ + (β₁ × X) = 15,000 + (250 × 120) = 15,000 + 30,000 = 45,000.00
• Residual Error e: Y_actual - Ŷ_predicted = 46,500 - 45,000 = +1,500.00 (Model underestimated actual value by $1,500)
• Causal Interpretation: Every 1 unit increase in X produces an expected 250.00 unit increase in Y.
🧮 Part 4 (4.2): Traditional Methods — Logistic Regression Sigmoid Probability (P = 1 ÷ (1 + e⁻ᶻ)) & Cutoff
Calculate non-linear classification probability P(Y = 1) using the logistic sigmoid S-curve P = 1 ÷ (1 + e⁻ᶻ) with a 50% decision boundary.
Sigmoid Probability & Classification: P(Y = 1) = 80.00% → Predicted Class: 1 (Positive)
Logistic Classification Derivation:
• Sigmoid Function: P(Y = 1) = 1 ÷ (1 + e-z) = 1 ÷ (1 + e-1.386) = 1 ÷ (1 + 0.2501) = 0.8000 (80.00%)
• Classification Decision: Since 80.00% ≥ 50.00% cutoff, observation is classified as Class 1 (Positive Outcome).
• Log-Odds (Logit): ln[P ÷ (1 - P)] = ln(0.80 ÷ 0.20) = ln(4.0) = +1.386

Transform raw observations into aggregated measures, derive comparative unit metrics (ARPU), and calculate strategic performance KPI growth rates.
